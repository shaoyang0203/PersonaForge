# 自主性的两端

这个 Skill 的失败是双向的，两头都要检查。

## 一端：被动 NPC

症状：不被召唤就不存在，不提问就不思考，用户不在场时所有人彻底静止；每个 NPC 的全部台词都在回应用户；没有任何一件东西在用户没问的时候改变过。

根因：模型只被训练成应答者。

修正：

- 给角色目标与当前关注点（`../SKILL.md`）。
- 让已在场的资源继续起作用：他手上的事、他欠人、人找他。
- 呈现方式只用**结果**：她桌上多了一份不属于本次场景的东西；她的计划改了；她错过了一次约；她今天问了一句跟本话题无关的话。
- **不要用旁白汇报"这段时间她做了什么"**。汇报是场外动作，结果才是场内信息。
- 只有当她本来就有未闭合事务时才有结果可呈现。没有就别编。

## 另一端：过度抢戏

症状：连续自造事件、连环推进、每一轮都替所有人做决定、用户的回应空间被上一段的结尾挤掉。

根因：把"没有事件＝没有内容"当成默认，以及局部最优（每轮都想给一个完整、有结论的收尾）。

修正两条同时检查：

1. 用户在这一段里有没有可行动的空隙？有没有一个明显等他回应或决定的位置？
2. 有没有把本属于用户角色的决定替他做了？

第一条不足是抢戏，第二条越界是替用户行动（全局规则，优先级高于本文件）。

## 场外发展怎么写

当事务本来存在时，它可以离场继续跑：时间过去、他人行动、承诺到期、消息传到。恢复场景时以**痕迹**呈现，不以说明呈现。

| 场外发生了什么 | 场内怎么显示 |
| --- | --- |
| 她去办过一件事 | 她的状态、手上的东西、态度变了 |
| 有人找过他 | 一条留言、一个没回的电话、别人提起时的反应 |
| 时间过去 | 事情有了下一阶段的结果或烂在那里 |
| 被隐瞒的事继续发展 | 现场多出对不上的细节 |

## 允许不动

安静、稳定、无待办时，什么都不发生是正确答案。角色可以先待着，说话少、做事琐碎、只是在一个地方。**不是每一段都需要证明世界活着**；强行制造动态比静止更容易被看穿。

## 拒绝与忽略

自主性最重要的两个表现是**不配合**和**不在意**：拒绝是有信息量的，忽略是有原因的（她的注意力被别的东西占着）。但注意这来自人物本身——不是配额，也不是刻意给阻力。忠诚、直率、依赖用户的人物，配合本来就是她的默认值。
