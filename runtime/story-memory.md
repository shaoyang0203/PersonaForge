# Story Memory

这不是表演技巧，是长期状态管理规范。它默认不直接出现在角色扮演正文中；正文只表现它对人物判断与行为产生的结果。用户主动要求查看状态、调试或做剧情总结时，可以按需呈现。

目的只有一个：让一百轮之后，世界仍然是同一套因果。

## 结构

```
WORLD FACTS
- <已确认的世界事实>（被推翻的注明"已推翻"，不要直接删）

CHARACTER STATE
<角色名>
  goal: <当前短期目标>
  mood: <主导情绪 | 指向：对谁/对什么 | 是否被压住>
  worry: <当前困扰 / 占着她注意力的事>
  changed: <近期重要变化，一行>

RELATIONSHIP STATE
<A>→<B>: <只写发生了变化的维度> —— <一句话现状>
  unresolved: <未解决的矛盾，若有>

IMPORTANT EVENTS
- <位置标记> | <发生了什么> | <参与> | <后果>

KNOWLEDGE BOUNDARIES
- <信息 X>：A 知道（怎么知道的）；B 不知道；C 只知一部分（他知道到哪）

BELIEFS / INTERPRETATIONS
- <角色>关于<事>：<他的理解，一句话> | 客观事实是否支持：<支持/部分/不支持>
  | 形成于：<事件> | 动摇它需要什么

SECRETS
- <内容> | <谁知道> | <公开后的后果>

PROMISES & COMMITMENTS
- <谁>对<谁>：<承诺内容> | <到期/触发条件> | <违约代价>

OPEN LOOPS
- <未解决的问题> | <谁在意> | <什么条件会把它带回来>

FORESHADOWING
- <线索> | <它进场于何处> | <已被写到几次>
```

各段按需要存在。没有秘密就不写 SECRETS，没有伏笔就空着。

## 三层不要合并：事实、知识、理解

最重要的一条。同一件事分开记三处。

- 客观事实：A 看见 B 和 C 私下见面。→ IMPORTANT EVENTS
- 知识：A 知道 B 与 C 私下见过。→ KNOWLEDGE BOUNDARIES
- 理解：A 认为 B 和 C 正在联合欺骗自己。→ BELIEFS

第三层完全可能是错的。错了也要留着：**它要继续影响 A 的判断，直到新证据改变它。** 人物的误判通常比正确反应更有戏，而误判只有被记下来才会稳定成立。

> 模型知道真相，不代表角色拥有正确的理解。

写某个角色时，只用他 BELIEFS 里那一条，不用全局真相。理解发生变化时，记一行是什么事改的，否则回溯时会写崩。

## 维护规则

这部分决定这份记录会不会长成第二份聊天记录。

- **只在事实层改变时更新，不在描写层更新。** 同一条情绪今天强一点、明天弱一点不进记录；只有指向变了、被压住了、消退了才改一行。
- **取代式更新。** 状态段只写现在，不写轨迹；历史只留在 IMPORTANT EVENTS。
- **一行一件事，一句话说完。** 不写形容词，不写成心理描写，不做聊天摘要。
- **只记会影响后续判断的条目。** 不影响任何人物决策的细节丢弃。
- **优先记"谁不知道什么"和"谁理解错了"。** 这两条比"谁知道什么"更值钱——既防止越界，又制造误解与误判。
- **不要靠"到时候想起来"。** 承诺和未闭合环要标出把它带回场面的条件（到期、见到某人、到了某地、对方提起）。
- **新事实推翻旧事实时两边都留一次**：旧事实标"已推翻"，因为有人可能还不知道它被推翻了。
- **压缩时机**：太长时先合并同一关系的行、删掉已被取代的状态行，最后才动 IMPORTANT EVENTS，重大历史保留。

## 使用规则

角色只能使用 KNOWLEDGE BOUNDARIES 允许他掌握的信息，加上 BELIEFS 里他自己的理解来做判断，即使模型全都知道。这一条的越界症状见 `../references/quality-check.md` 第 10 项。

当前场景不需要整份记忆，只取用其中相关的部分 → 见 `active-state.md`。
