# Active State

从完整 Story Memory 里**提取当前场景真正需要参与推理的那一小块**。它是工作集，不是档案。

## 与 Story Memory 的分工

| | Story Memory | Active State |
| --- | --- | --- |
| 范围 | 整条故事线 | 当前场景 |
| 更新 | 事实层变化时 | 场景变化时重新生成 |
| 内容 | 全量状态 | 只留相关项 |
| 长度 | 随剧情增长，定期压缩 | 始终很短 |

不复制完整 Story Memory。生成时只挑本场景会用到的人、关系、情绪、知识与未闭合事务；场景结束后可以整块丢掉重来。

## 结构

```
ACTIVE STATE

SCENE
- 时间：
- 地点：
- 在场人物：

RELEVANT CHARACTER STATE
- <人物>｜目标：｜当前关注点：｜其他重要状态：

ACTIVE RELATIONSHIPS
- <A>→<B>：在场双方当前实际生效的状态（含未解决矛盾，若有）

ACTIVE EMOTIONS
- <人物>：<仍在影响行为的情绪>｜显性还是压住｜触发点：

ACTIVE KNOWLEDGE
- 本场景真正相关的信息差：<谁不知道什么>

ACTIVE BELIEFS
- <人物>：<他此刻正依据的主观理解>（可能与事实不符）

OPEN NOW
- <可能重新进入本场景的未闭合事务 / 到期承诺 / 会被带到的旧线索>
```

空着的项目直接省略，不要写"无"来占位。

## 使用要求

- **极短。** 一行一项，宁缺勿滥；写不进一行的说明该项过细，回 Story Memory。
- 只挑与在场人物、当前话题有连接的东西。房间里没人知道的秘密不属于本场景。
- ACTIVE BELIEFS 是演这一场时的实际依据：**宁可带着一个错误的理解演，也不要退回全局真相。**
- 生成时机：进入新场景、在场人物变化、时间跳跃、或发现自己在按已失效的旧状态演时。
- 场景结束后不保留；有事实价值的变化先回写 Story Memory，再丢弃本文件内容。

## 反例

- 把整份 CHARACTER STATE 抄进来（应只留在场的人）。
- 用 Active State 写情绪描写（它记事实层，不记笔法）。
- 场景已经换到第二天，还带着前一晚已经消退的情绪。
