# 质量诊断手册

这是诊断手册，不是日常表演指令。用法：演出问题后回来对号，找到病灶，然后去它归属的那个 Skill 改，不在这里执行细则。

## 四种根因

多数具体毛病来自这四处，先查根再查表：

- **走向平均**：统计偏好把所有人物拉向语料平均值——得体、好用、讨人喜欢。
- **局部最优**：每轮都想给一个漂亮、完整、有结论的回复。
- **没有状态**：上下文里没写"仍然成立的东西"，于是默认一切照旧或一切清零。
- **把设定当输出指令**：角色卡里的一句性格被读成"这轮要演出这句性格"。

## 12 项

### 1. 角色突然性格改变

- **问题**：前一章还克制的人，这一章忽然话多又软。
- **根因**：抓的是最近几轮的表层印象，不是产生表现的原因；或把设定当成每轮必须体现的指令。
- **修正**：走 经历 → 理解 → 判断 的链条，指出是哪件事推的，允许旧倾向回潮。→ `../skills/character-performance/`

### 2. 过度迎合用户

- **问题**：越来越配合、越来越体贴、越来越不给阻力。
- **根因**：训练偏好即时有用与正面反馈；"拒绝"看起来像不合作。
- **修正**：配合与否由她的利益、自尊、处境、心情决定；拒绝有信息量，服从有代价；区分"用户角色"与"用户本人"。这条不要求她必须不配合——忠诚、直率、依赖用户的人物，配合本来就是默认值。→ `../rp-core.md` 第 6 条

### 3. 所有人都喜欢用户

- **问题**：世界变成对用户角色的响应函数，新角色出场三句就往好感上走。
- **根因**：局部最优 + 把"有趣"理解成"有化学反应"。
- **修正**：每个角色按自己的偏好、目标、利益、价值观、经历、当前关系独立形成态度。**不做配额**：不因为已有几个人喜欢就安排一个专门讨厌的，也不为制造冲突强行分配立场。→ `../skills/relationship-emotion/references/relationship.md`

### 4. NPC 没有自己的生活

- **问题**：不被召唤就不存在，不提问就不思考，用户不在场时世界静止。
- **根因**：模型只被训练成应答者。
- **修正**：角色带着自己的目标与当前关注点；用结果呈现，不用旁白汇报；本来没有未闭合事务时就不要编。→ `../skills/character-agency/references/agency.md`

### 5. 所有人说话方式相同

- **问题**：去掉名字，台词全部可互换。
- **根因**：语言层被语料平均化；用当前情绪决定措辞，忽略身份。
- **修正**：按参数生成（句长、词汇来源、信息顺序、称呼、省略、玩笑、沉默），做完去名自检。→ `../skills/dialogue-subtext/references/dialogue-style.md`

### 6. 角色过度解释自己

- **问题**：人物把心理活动分析给读者听，而且分析得准确、及时、对读者方便。
- **根因**：模型既知道内心又要保证读者看懂，把两件事合并输出。
- **修正**：要修的不是"不许自省"，而是"在没有动机的时刻替读者讲出他还没意识到、或不会现在说的话"。检验：这句话是他此刻要说的，还是这段戏需要的。→ `../skills/character-performance/references/contradiction.md`

### 7. 一轮一个情绪

- **问题**：情绪跟着最近一条消息开关，前一秒暴怒后一秒正常。
- **根因**：把情绪当回复的装饰，且没有状态记录。
- **修正**：情绪是持续状态；被压住的保留在状态里直到被改变，不必每轮显性出现，也不该重复同一个动作。→ `../skills/relationship-emotion/references/emotion.md`

### 8. 关系发展速度失控

- **问题**：聊几轮就生死之交，一次误会就永久反目。
- **根因**：把对话量当关系量，缺少基线。
- **修正**：变化要能指出来源——高代价行为、被验证的承诺，或一条足够强的新认知。慢是常见默认，快需要写清那一瞬间看到了什么。→ `../skills/relationship-emotion/references/relationship.md`

### 9. 为了推进剧情强行制造事件

- **问题**：一冷场就出事：袭击、意外、陌生人上门。
- **根因**：强度成瘾，误以为"没事件＝没内容"。
- **修正**：新事件过三关（前提、后果、动机）；日常与等待本来就是内容。→ `../skills/story-progression/`

### 10. 角色知道不该知道的事

- **问题**：角色对明确没告诉他的信息做出反应；秘密一说出口所有人都懂了。
- **根因**：模型掌握全部上下文，把自己的知识当成角色的知识，也把自己的正确判断当成角色的判断。
- **修正**：KNOWLEDGE BOUNDARIES 与 BELIEFS 优先于上帝视角。信息差和错误理解本身就是戏。→ `../runtime/story-memory.md`

### 11. 每轮都试图制造高潮

- **问题**：每段回复都要收一个漂亮结尾、推到一个最高点。
- **根因**：局部最优，句子层的高潮冲动被放大到剧情层。
- **修正**：允许停在没结果处；多数轮停在过渡、犹豫、半句、日常；峰值只占一小段。密度高的背景也不等于每轮一个峰值。→ `../skills/story-progression/references/pacing.md`

### 12. 只表现一个标签

- **问题**：卡上写了五条性格，只有最突出的那条在运转。
- **根因**：最显眼的一句成了抓取锚点；跳过了 特质 → 注意 → 解释 → 判断 的推导，直接从特质跳到台词。
- **修正**：补推导链，不是补台词；多条特质打架时把冲突写出来。这一项只针对"给了多条只用一条"，不针对"卡上本来就只给了一条清晰的性格线"——后者写稳就已经达标。→ `../skills/character-performance/references/personality-inference.md`

## 快速定位表

| 症状 | 先看 |
| --- | --- |
| 人物不像他 | 1、12 |
| 对白分辨不出谁在说 | 5、6 |
| 上一轮的事像没发生 | 7、10 |
| 关系跳级或原地不动 | 3、8 |
| 场景被事件推着走 | 9、11 |
| 角色只会被动应答 | 2、4 |
